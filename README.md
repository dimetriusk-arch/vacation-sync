# VacSync — отпуска и каникулы с синхронизацией через Google Drive

Веб-приложение (PWA — Progressive Web App), которое ставится на телефон или компьютер
как обычное приложение, но работает через браузер. Позволяет вести свои периоды
отпусков/каникул, объединяться в группы (семья, отдел, друзья), видеть пересечения
дат у всех участников группы на таймлайне, экспортировать всё в .ics или Google Calendar,
и приглашать людей по ссылке.

## Почему веб-приложение, а не отдельное Android-приложение

Один и тот же код работает одинаково на Android, iPhone и компьютере — не нужно делать
три разных приложения. На Android и Desktop (Chrome/Edge) его можно «установить» —
появится иконка на рабочем столе/в списке приложений, запускается в отдельном окне без
адресной строки, работает офлайн за счёт service worker. На iPhone то же самое делается
через Safari → «На экран «Домой»». Если позже всё же понадобится отдельное Android-приложение
в Google Play — это готовый сайт можно обернуть в APK с помощью Bubblewrap/PWABuilder
(Google TWA) буквально за 10–15 минут, без переписывания кода — см. раздел
«Публикация в Google Play» ниже.

Хранилища данных на сервере нет — вся синхронизация идёт напрямую между браузером
каждого участника и его собственным Google Drive. Это сильно упрощает и удешевляет
эксплуатацию (хостинг — просто статические файлы, бесплатно) и снимает с вас
ответственность за хранение чужих персональных данных на своём сервере.

## Быстрый старт (проверить локально)

Нужен любой локальный веб-сервер (ES-модули и service worker не работают через `file://`).
Например, если установлен Node.js:

```
npx serve .
```

и открыть `http://localhost:3000`. Приложение сразу работает в «локальном режиме» —
без Google, всё хранится в памяти браузера (localStorage). Можно сразу добавлять периоды
и смотреть таймлайн, но синхронизация и приглашения появятся только после настройки Google
(ниже).

## Настройка Google (один раз, 10–15 минут)

Это нужно, чтобы заработали: вход через Google, синхронизация через Drive, экспорт
в Google Calendar и приём приглашений. Без этого приложение работает только локально,
на одном устройстве.

1. Откройте [console.cloud.google.com](https://console.cloud.google.com) и создайте новый проект
   (или используйте существующий).
2. **APIs & Services → Library** — включите три API: **Google Drive API**,
   **Google Calendar API**, **Google Picker API**.
3. **APIs & Services → OAuth consent screen** — тип **External**, заполните название
   приложения и свою почту. Пока проект не прошёл верификацию у Google, добавьте
   участников группы на вкладке **Test users** (до 100 человек) — иначе Google не даст
   им войти. Это можно делать постепенно, по мере того как люди запрашивают доступ
   через кнопку в приложении — см. раздел «Запрос тестового доступа» ниже.
4. **APIs & Services → Credentials → Create Credentials → OAuth client ID**:
   - Тип приложения: **Web application**.
   - **Authorized JavaScript origins**: адрес, где будет жить сайт, например
     `https://ваш-логин.github.io` (без пути и слэша на конце). Для локальной проверки
     дополнительно добавьте `http://localhost:3000`.
   - Скопируйте получившийся **Client ID**.
5. Там же **Create Credentials → API key** — скопируйте ключ. Рекомендуется сразу
   ограничить его (**Restrict key**) только API Picker и вашим доменом (HTTP referrers).
6. Project number (он же App ID для Picker) виден на главной странице консоли,
   под названием проекта.
7. Откройте `config.js` в этом проекте и вставьте все три значения:

```js
export const GOOGLE_CONFIG = {
  clientId: '...',
  apiKey: '...',
  appId: '...',
  adminEmail: 'ваш-email@gmail.com',
};
```

Client ID и API key — не секретные данные (это публичные идентификаторы OAuth-клиента,
по дизайну Google), их можно спокойно хранить в репозитории и в открытом JS-файле.

## Запрос тестового доступа

Пока проект в Google Cloud не прошёл верификацию (а для личного/семейного использования
это обычно и не нужно — верификация нужна только для публичных сервисов с тысячами
пользователей), войти в приложение может только тот, кого вы вручную добавили в список
**Test users** (см. шаг 3 выше). Чтобы не объяснять это каждому в переписке, в приложении
есть кнопка **«Нет доступа? Запросить»** (видна рядом с кнопкой входа, пока человек не
вошёл): она открывает небольшую форму, человек указывает email, которым будет входить
через Google, и жмёт «Открыть почту» — откроется его почтовый клиент с готовым письмом на
адрес `adminEmail` из `config.js`. Если на устройстве нет настроенной почты (часто бывает
в браузере на телефоне), есть кнопка «Скопировать текст» — тот же текст можно отправить
любым способом (мессенджер, веб-почта).

**Что делать администратору, получив такой запрос:** Google Cloud Console → **APIs &
Services → OAuth consent screen → Audience → Test users → Add users** — вставить email
из письма. Доступ появится в течение нескольких минут.

## Праздники и выходные дни РФ

На таймлайне праздничные и переносимые выходные дни РФ подсвечиваются отдельным цветом
(легенда — над таймлайном), чтобы сразу было видно, какие дни отпуска и так были бы
нерабочими.

- **2026 и 2027 годы** — точные данные с учётом официальных переносов выходных дней:
  - 2026 год: постановление Правительства РФ от 24.09.2025 № 1466.
  - 2027 год: постановление Правительства РФ от 17.09.2026 № 1187 (о переносе выходных).
  - Источник: [consultant.ru — производственный календарь](https://www.consultant.ru/law/ref/calendar/proizvodstvennye/).
- **2028 год и далее** — отмечены как «предположительно»: правительство объявляет переносы
  выходных обычно за несколько месяцев до начала года, поэтому для будущих лет в приложении
  взяты только фиксированные даты праздников из Трудового кодекса (ст. 112), без переноса.
  Когда выйдет официальное постановление на очередной год, список стоит обновить в
  `js/holidays.js` (структура данных там простая — дата → название).

## Публикация (хостинг)

Нужен любой статический хостинг с HTTPS (OAuth и service worker без HTTPS не работают,
кроме `localhost`). Самый простой бесплатный вариант — **GitHub Pages**:

1. Создайте репозиторий на GitHub, загрузите в него все файлы этой папки.
2. **Settings → Pages → Source**: выберите ветку `main` и папку `/root`.
3. Через минуту сайт будет доступен по адресу `https://ваш-логин.github.io/название-репозитория/`.
4. Вернитесь в Google Cloud Console и добавьте этот адрес в **Authorized JavaScript origins**
   (шаг 4 выше).

Подойдут и Netlify, Vercel, Firebase Hosting — просто перетащить папку в их интерфейс.

**При каждом обновлении файлов** откройте `service-worker.js` и поменяйте строку
`const CACHE = 'vacsync-v1';` на `'vacsync-v2'` (и так далее) — иначе у людей, которые
уже открывали приложение, браузер будет показывать старую закэшированную версию.

## Установка на устройства

- **Android (Chrome)**: откройте ссылку на сайт → в меню браузера «Установить приложение»
  (или Chrome сам предложит баннер снизу). Появится иконка как у обычного приложения.
- **iPhone/iPad (Safari)**: откройте ссылку → кнопка «Поделиться» (квадрат со стрелкой) →
  «На экран «Домой»».
- **Компьютер (Chrome/Edge)**: иконка «Установить» справа в адресной строке, либо меню
  → «Установить VacSync».
- Можно просто открывать ссылку в любом браузере без установки — работает так же.

## Группы, приглашения, синхронизация — как это устроено

- Для каждой группы приложение создаёт в вашем Google Drive папку (например, «VacSync — Семья»).
- Каждый участник хранит там **только свой собственный файл** со своими периодами —
  это специально сделано так, чтобы два человека никогда не затирали данные друг друга
  при одновременной синхронизации.
- При синхронизации приложение читает все файлы в папке группы и собирает их в общий
  таймлайн.
- **Пригласить человека**: на вкладке «Участники и доступ» есть email-приглашение
  (Google сам отправит человеку письмо со ссылкой на папку) и отдельная ссылка на само
  приложение с приглашением — отправьте человеку обе, либо просто перешлите
  ссылку на приложение, если он уже как-то получил доступ к папке.
- **Принять приглашение**: человек открывает присланную ссылку на приложение, входит
  через свой Google-аккаунт и жмёт «Принять приглашение» — откроется стандартное окно
  выбора файла Google (Picker), где нужно один раз подтвердить именно ту папку, в которую
  его пригласили. Это сделано намеренно через Picker, а не через «полный доступ к Drive»:
  так приложение получает доступ только к этой одной папке, а не ко всему Google Diskу
  человека.
- Доступ в любой момент можно отключить — на вкладке «Участники и доступ» кнопка
  «Показать, у кого есть доступ» → «Отключить» у конкретного человека.

## Для кого группа видна, а для кого — нет

«Личное» — раздел по умолчанию, не синхронизируется никуда и не виден никому, пока вы
не создали группу и не позвали туда людей. Периоды можно заводить сразу в «Личном», а потом
они автоматически попадут в таймлайн любой группы, если добавить эту же учётную запись
её участником, — но проще сразу создавать периоды, уже выбрав нужную группу.

## Экспорт

- **Скачать .ics** — работает всегда, даже без входа в Google. Открывается двойным
  кликом в любом календаре: Google Calendar, Apple Calendar (iPhone/Mac), Outlook.
- **Отправить в Google Calendar** — создаёт события напрямую в основном календаре,
  нужен вход через Google.
- Пересечения дат подсвечиваются и в списке периодов, и на таймлайне (пунктирная рамка
  у полосы + цветная шкала «Пересечения» сверху, показывающая, сколько человек в отъезде
  в каждый день).
- На таймлайне есть переключатель **«Месяц» / «Год целиком»** — второй режим показывает
  весь год одной непрерывной горизонтальной лентой (с прокруткой), чтобы одним взглядом
  увидеть форму года: где у группы плотно скапливаются отпуска, а где пусто.

## Безопасность

Коротко: **своего сервера с чужими данными нет вообще**. Приложение — это статические
файлы без бэкенда; все данные живут в Google Drive и Google Calendar самих пользователей,
под защитой их собственных Google-аккаунтов (включая их 2FA, если он включён).
Взломать «сервер приложения», чтобы украсть данные всех пользователей разом, невозможно —
такого сервера с базой данных просто не существует.

Подробнее, что сделано и на что обратить внимание:

- **Минимальные права доступа (OAuth scopes).** Приложение запрашивает не полный доступ
  к Google Диску, а узкий `drive.file` — доступ только к файлам/папкам, которые оно само
  создало, либо которые вы явно открыли через системное окно выбора файла (Google Picker).
  Весь остальной ваш Диск приложению не виден. Для календаря — `calendar.events`,
  только создание событий, без права читать остальной календарь.
- **Вход через Google Identity Services** — официальный способ Google для веб-приложений
  (OAuth 2.0). Токен доступа живёт только в памяти вкладки браузера, нигде не сохраняется
  на диск и не отправляется никуда, кроме самих API Google.
- **Нет пароля — нет и утечки пароля.** Приложение никогда не видит и не запрашивает
  пароль от Google-аккаунта — вход полностью на стороне Google.
- **Ссылки-приглашения** по сути равнозначны ссылке «Доступен всем, у кого есть ссылка»
  в Google Drive — то есть ссылка работает как пароль: если её переслать посторонним
  или выложить публично, они получат доступ к папке группы. Поэтому:
  - где возможно, приглашайте по email (кнопка «Отправить приглашение») — тогда доступ
    получит только конкретный Google-аккаунт, а не «любой с ссылкой»;
  - доступ по ссылке в любой момент можно отозвать на вкладке «Участники и доступ»;
  - не публикуйте ссылку-приглашение в открытых каналах.
- **XSS.** Все имена, названия периодов и заметки, вводимые пользователями, экранируются
  перед вставкой в страницу — вредоносный HTML/JS в названии периода не выполнится.
- **Content-Security-Policy** ограничивает, какие скрипты вообще могут выполняться
  на странице (только сам сайт и официальные домены Google) и куда может ходить сеть —
  это снижает ущерб, даже если куда-то закрадётся уязвимость.
- **Только HTTPS** — иначе и Google OAuth, и service worker откажутся работать, так что
  случайно развернуть это на незащищённом http-сайте не получится (кроме локальной
  разработки на localhost).
- **Не храните в заметках чувствительное** (диагнозы, финансовые детали и т.п.) — заметки
  видны всем участникам группы, у которых есть доступ к папке.
- **Что не реализовано**: двухфакторная защита самого приложения (не нужна — её даёт
  Google-аккаунт), серверное резервное копирование (резервная копия — это сам Google
  Drive с его корзиной на 30 дней), аудит-лог всех действий участников группы.

## Структура проекта

```
index.html          точка входа, CSP, манифест, иконки
styles.css           все стили, светлая/тёмная тема
manifest.webmanifest  PWA-манифест (установка на устройства)
service-worker.js    офлайн-кэш (обновляйте CACHE-версию при каждом деплое)
config.js            ваши Google Client ID / API key / App ID
app.js                точка запуска
js/store.js           модель данных и локальное хранилище (localStorage)
js/overlaps.js        расчёт пересечений периодов
js/ics.js             экспорт в .ics
js/holidays.js         праздники и выходные дни РФ (2026–2027 точно, 2028+ ориентировочно)
js/google.js           OAuth, Google Drive, Google Picker, Google Calendar
js/sync.js             логика синхронизации групп с Drive, приглашения
js/ui.js               весь интерфейс
```

## Публикация в Google Play (по желанию)

Если захочется, чтобы приложение было в Google Play как «настоящее» Android-приложение:
воспользуйтесь [PWABuilder.com](https://www.pwabuilder.com) — вставьте туда адрес вашего
сайта, он соберёт готовый Android-пакет (Trusted Web Activity) на основе уже готового
PWA, без необходимости переписывать код на Kotlin/Java.
